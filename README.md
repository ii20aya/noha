# دعوة محمد يونس ونهى أشرف

## تشغيل النسخة المحلية

يتطلب Node.js 22 أو أحدث.

```powershell
npm.cmd run build
npm.cmd run preview
```

المعاينة على http://localhost:4173. أعد البناء بعد كل تعديل.

## البيانات والصور

النصوص واللغة والموعد في src/content.js.
موعد الفرح 23 ديسمبر 2026. العد التنازلي لبداية اليوم بتوقيت مصر إلى أن تتحدد الساعة.
المكان قاعة الأوركيد، الدور الثاني، فندق توليب، بني سويف.
الخريطة والاتجاهات تستخدم الإحداثيات 29.062962,31.100927 الموجودة في مركز رابط Bing الذي أرسلته المالكة. هذه إحداثيات مركز العرض في الرابط وليست معرّف Google Place. يلزم تأكيد موضع المدخل إذا اختلف عن مركز العرض.
ضع رابط الاتجاهات المؤكد في venueMapUrl، ومن Google Maps اختر Share ثم Embed a map وانسخ رابط src فقط إلى venueEmbedUrl.

الرسومات الأصلية المرسلة من المالكة في monogram-ar.svg وmonogram-en.svg. يتغير الرسم حسب اللغة. تم دمج كل رسم داخل فيديو فتح مستقل وصورة بداية مستقلة، بدون طبقة ختم متحركة منفصلة.
الصورة الأصلية للطفولة داخل الإطار في public/assets/together.jpg.

## الصوت

تم تنزيل ملف sound.mp4 الأصلي من الدعوة المرجعية بطلب المالكة، وحفظه في public/assets/wedding-sound.mp4 وربطه بالموسيقى. اختُبر تشغيله وكتمه في المتصفح.
ضع ملف الزفّة في public/assets وحدد مساره في zaffaAudio.
تبدأ الزفّة بعد انتهاء الفتح مع زر صوت في الأعلى وزر تشغيل احتياطي إذا منع المتصفح التشغيل التلقائي.
ضع مقطع الافتتاحية المصرّح باستخدامه في openingAudio. يتوقف قبل بدء الزفّة.
البحث يؤكد مشهد كتابة حرف الميم على السبورة، لكن صياغة «بالراحة / مينة» وتوقيتها لم يتم التحقق منهما من تسجيل أصلي.
اقتراح تسجيل أصلي بصوت صاحب الدعوة مدته 3 ثوانٍ «ميم محمد… ونون نهى… والفرحة تجمعنا». هذا نص مقترح جديد.

## الرسائل والاحتفاظ بها

حسب طلب المالكة الأخير، الرسائل تبقى محفوظة بدون موعد حذف تلقائي.
الربط الموجود هو Google Sheets. لا توجد مهمة حذف تلقائي أو API لحذف الرسائل.
الشيت الخاصة هي لوحة عرض الأسماء والحضور والمرافقين والرسائل، ولا يملك زائر الدعوة صلاحية قراءتها.

1. أنشئ Google Sheet ثم Extensions → Apps Script.
2. انسخ scripts/rsvp.gs.
3. في Project Settings → Script properties أضف RSVP_SHEET_ID ومعه RSVP_SCRIPT_SECRET بقيمة عشوائية طويلة.
4. انشر Deploy → New deployment → Web app. اختر التنفيذ بحساب المالك والوصول Anyone، ثم احتفظ برابط /exec.
5. أضف RSVP_SCRIPT_URL وRSVP_SCRIPT_SECRET إلى متغيرات بيئة Vercel. السر يبقى على السيرفر.
6. أعد النشر وأرسل ردًا تجريبيًا. تحقق من ظهوره في ورقة RSVP.
7. افتح الشيت من حسابك لقراءة الرسائل. يمكن تنزيل نسخة CSV أو Excel للاحتفاظ بنسخة مستقلة.

## Firebase بعد موافقة المالكة

الربط موجود في api/rsvp.js وscripts/firestore.js. تُحفظ الأسماء والحضور وعدد المرافقين والرسالة والتوقيت في مجموعة rsvps. تكرار الإرسال بنفس المعرّف يحتفظ بأول رد.
Firebase هو الخيار الأساسي عند ضبط متغيراته الثلاثة. يبقى Google Sheets مدعومًا لبيانات الربط السابقة.
لا توجد سياسة TTL أو مهمة حذف. تظل الردود محفوظة إلى أن يزيلها المالك بنفسه أو يغيّر حالة حسابه.

1. افتحي https://console.firebase.google.com واختاري Add project، ثم أنشئي مشروعًا بخطة Spark المجانية. Google Analytics اختياري.
2. اختاري Build → Firestore Database → Create database. اختاري Standard edition واسم قاعدة البيانات (default) ثم Production mode ومنطقة مناسبة.
3. من تبويب Rules انسخي scripts/firestore.rules ثم Publish. هذا يمنع وصول زوار الدعوة المباشر للبيانات.
4. من Project settings → Service accounts → Firebase Admin SDK اختاري Generate new private key. احتفظي بملف JSON على جهازك في مكان خاص خارج المشروع.
5. من Vercel → Project → Settings → Environment Variables أضيفي القيم التالية من ملف JSON:
   - FIREBASE_PROJECT_ID ← project_id
   - FIREBASE_CLIENT_EMAIL ← client_email
   - FIREBASE_PRIVATE_KEY ← private_key كاملة بما فيها BEGIN وEND. يمكن لصقها بأسطر حقيقية أو باستخدام تسلسل \n.
6. هذه المتغيرات للسيرفر فقط. لا تضعي ملف JSON أو المفتاح داخل src أو public أو مستودع Git.
7. أعيدي Deploy من Vercel، وافتحي الدعوة وأرسلي ردًا تجريبيًا.
8. افتحي Firebase Console → Firestore Database → Data → rsvps لقراءة ردود الضيوف. هذه هي لوحة البيانات الخاصة بحسابك.
9. تأكدي أن الرد يظهر فعلًا قبل إرسال الدعوة للضيوف. الاختبارات المحلية تستخدم خدمة بديلة لأن الحساب الحقيقي لم يتم إعداده بعد.

الحساب يحتاج صلاحية كتابة Firestore للسيرفر عبر IAM. حساب Firebase Admin المنشأ من إعدادات المشروع هو المسار المعتاد، وتوضح وثائق Firebase طريقة إدارة هذه الصلاحيات.
https://firebase.google.com/docs/admin/setup
https://firebase.google.com/docs/firestore/security/iam

## النشر على Vercel

1. ارفع محتويات المشروع إلى مستودع GitHub خاص.
2. افتح https://vercel.com/new واختر Import Git Repository ثم المستودع.
3. Framework Preset هو Other، وأمر البناء npm run build، ومجلد الإخراج dist. هذه الإعدادات موجودة في vercel.json.
4. اضبط متغيرات البيئة الخاصة بوسيلة حفظ الرسائل المختارة ثم Deploy.
5. اختبر رابط Vercel على الهاتف. افتح الظرف وبدّل اللغة وأرسل رسالة اختبارية وتحقق من حفظها من حساب المالك.
6. راجعي الخريطة على إحداثيات الرابط المرسل، وأضيفي الصوت وأعيدي النشر قبل إرسال الرابط للضيوف.

المشروع لم يُنشر بعد. Firebase جاهز للربط بعد إنشاء الحساب وإضافة متغيرات البيئة. يلزم اختبار الحفظ بالحساب الحقيقي قبل المشاركة.
